# UI 변경 제안

Figma 11주차 화면을 실제로 구현하면서 발견한 점입니다. 각 제안은 **현재 → 문제 → 제안 → 근거** 순서이고, 근거는 접근성 기준 · 플랫폼 가이드 · Figma 색 규칙 · 측정값입니다.

## 요약

| # | 제안 | 우선순위 | 작업량 |
| --- | --- | --- | --- |
| U1 | 보조 글자 회색을 진하게 | 높음 | 작음 |
| U2 | 초록(받을 수 있음)을 진하게 | 높음 | 작음 |
| U3 | 목록에서 '지금 받을 수 있는 혜택' 구분 | 높음 | 중간 |
| U4 | 북마크 · 닫기 버튼 터치 영역 44px | 중간 | 작음 |
| U5 | 지도 탭은 상단 UI를 줄이기 | 중간 | 중간 |

### U1. 보조 글자 회색을 진하게

- **현재**: 거리 · 즐겨찾기 수 · 조건 칩 · 안내 문구가 `text/3 #8B909C` (12px 안팎)
- **문제**: 흰 배경에서 명암비 **3.20:1**, 연회색 배경(`#F4F5F7`, 조건 칩)에서는 **2.93:1**. WCAG AA 기준(일반 글자 **4.5:1**)에 못 미침. 조건 칩은 "2명 이상" 같은 **혜택을 받는 조건**이라 놓치면 안 되는 정보
- **제안**: `text/3`을 `#636977`로 → 흰 배경 **5.50:1**, 연회색 **5.04:1**. 위계는 `text/2 #5B6170`(6.20:1)과 여전히 구분됨
- **근거**: WCAG 2.2 · 1.4.3 대비(최소). 수치는 상대 휘도 공식으로 계산

### U2. 초록(받을 수 있음)을 진하게

- **현재**: '영업 중', '4명 모두 나눴어요'가 `secondary/strong #0F9F78` (13~14px)
- **문제**: 흰 배경 **3.36:1**로 AA 미달. 굵은 14px는 '큰 글자'(굵게 18.66px 이상)가 아니라 4.5:1이 필요
- **제안**: `#0A7F60`(**4.98:1**)으로. 색상(초록 계열)은 유지해서 Figma 색 규칙의 뜻은 그대로
- **근거**: WCAG 2.2 · 1.4.3

### U3. 목록에서 '지금 받을 수 있는 혜택' 구분

- **현재**: 목록 줄에 혜택이 모두 같은 모양. "4명 이상" 혜택도 2명으로 설정한 사용자에게 똑같이 보이고, 상세에 들어가야 '받을 수 없어요'를 알 수 있음
- **문제**: 서비스 목표가 "**내가** 받을 수 있는 혜택"인데, 목록에서 그걸 판단할 수 없음. 조건 설정을 해도 목록이 거의 안 바뀌어 설정한 보람이 없음
- **제안**: 조건(인원)을 못 채운 혜택은 목록에서 글자를 `text/3`으로 흐리게 + 조건 칩을 "2명 더 필요"로 바꿈. 받을 수 있는 혜택만 있는 가게를 먼저 보는 '받을 수 있는 것만' 토글도 검토
- **근거**: Figma 색 규칙 "초록 = 지금 받을 수 있는 상태"를 목록까지 확장. Nielsen 휴리스틱 #1 시스템 상태의 가시성 (조건 설정의 결과가 바로 보여야 함)

### U4. 북마크 · 닫기 버튼 터치 영역 44px

- **현재**: 목록 북마크 40×40, 모달 닫기 32×32
- **문제**: 한 손 엄지로 누를 때 옆 줄(매장 상세 열기)을 잘못 누르기 쉬움. 특히 북마크는 줄 전체가 눌리는 영역 안에 있음
- **제안**: 보이는 크기는 그대로 두고 터치 영역만 44×44로 (padding 또는 `::after`로 확장)
- **근거**: Apple HIG 최소 터치 영역 44×44pt, Material 48×48dp. WCAG 2.2 · 2.5.8(최소 24px)은 이미 충족하지만 모바일 가이드 기준에는 미달

### U5. 지도 탭은 상단 UI를 줄이기

- **현재**: 지도 탭도 목록과 같은 상단 UI(로고 · 조건 · 검색 · 업종 칩, 약 172px)
- **문제**: 높이 667px 화면(iPhone SE)에서 하단 탭(약 64px)까지 빼면 지도 영역이 **약 431px**, 화면의 65% 정도. 고른 가게 카드(약 94px)가 올라오면 지도는 더 좁아짐
- **제안**: 지도 탭에서는 검색창을 아이콘으로 접고, 조건 알약 + 업종 칩을 한 줄로. 지도를 위로 끌면 상단 UI가 숨는 방식도 가능
- **근거**: 지도 화면의 주 콘텐츠는 지도. 같은 조건을 쓰는 건 유지(Figma 설명 "같은 조건 그대로 지도에서")하되 공간은 지도에 양보

### U6. 상세 혜택 체크를 받을 수 있으면 초록

- **현재**: 상세 혜택 카드의 조건 체크(✓ 2명 이상 방문)가 항상 회색
- **문제**: 체크 표시가 '이미 충족함'처럼 보이지만 실제 충족 여부와 상관없음 → 의미가 애매
- **제안**: 사용자 조건으로 충족한 조건은 초록 체크, 못 채운 조건은 회색 원(○) + "2명 더 필요"
- **근거**: Figma 색 규칙 초록의 뜻("4명 모두 나눴어요" 같은 조건 충족 표시)과 일치시키기

### U7. 업종 칩에 개수, 0곳이면 흐리게

- **현재**: '기타'를 누르면 빈 결과
- **문제**: 눌러 보기 전에는 결과가 없다는 걸 알 수 없음 (헛걸음 탭)
- **제안**: `식당 7` 처럼 지금 조건의 개수를 작게 표시, 0곳이면 흐리게
- **근거**: 사용자가 행동하기 전에 결과를 예측할 수 있게 (Nielsen #6 기억보다 인식)

### U8. 조건 알약 표기 정리

- **현재**: 단과대가 섞이면 "공학대학 외 2곳 · 4명"
- **문제**: 알약이 길어져 로고 옆 한 줄에 겨우 들어감. '외 2곳'은 가게 수처럼 읽힐 수 있음
- **제안**: "공학대학 외 2개 단과대 · 4명" 대신 짧게 **"섞인 단과대 · 4명"** 또는 "공학 +2 · 4명"
- **근거**: '곳'은 앱 전체에서 가게 수 단위로 쓰고 있어 같은 단위를 다른 뜻으로 쓰지 않기 (색 규칙의 "같은 색은 한 가지 뜻만"과 같은 원칙)

---

## 반영 방법

U1 · U2 · U4 · U6 · U7은 CSS · 컴포넌트 수정만으로 가능하고, Figma 색 변수(`text/3`, `secondary/strong`)도 같이 바꿔야 디자인과 코드가 어긋나지 않습니다. U3 · U5는 화면 설계 변경이라 Figma에서 먼저 시안을 만든 뒤 구현하는 것을 권장합니다.

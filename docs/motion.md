# 화면 안 애니메이션 근거

제휴모아의 애니메이션은 **장식이 아니라 정보**입니다.
"무엇이 바뀌었는지" 또는 "이 화면이 어디서 왔는지"를 알려 줄 때만 쓰고, 그 외에는 쓰지 않습니다.

## 원칙

1. **상태 변화나 공간 관계를 알려 줄 때만** 움직입니다. 보기 좋으라고 넣지 않습니다.
2. **짧게**: 대부분 150~260ms. 사용자가 애니메이션을 기다리게 만들지 않습니다.
   (Material Design은 모바일 화면 전환을 200~300ms로 권장하고, 작은 요소 변화는 100ms 안팎으로 권장합니다.)
3. **색 규칙과 같이 갑니다**: 노랑은 스크랩, 파랑은 고른 것. 움직임은 그 색이 바뀌는 순간을 짚어 줄 뿐 새로운 뜻을 만들지 않습니다.
4. **움직임 줄이기 존중**: OS에서 `prefers-reduced-motion`을 켠 사용자는 모든 화면 안 애니메이션이 꺼집니다. 상태 변화는 색으로 그대로 보입니다. (WCAG 2.3.3 Animation from Interactions)
5. **transform·opacity만** 움직여서 저사양 폰에서도 끊기지 않게 합니다. (예외: 지도 핀 크기 0.18초)

## 일부러 넣지 않은 것

| 어디 | 이유 |
| --- | --- |
| 하단 탭 전환 | 탭은 같은 높이의 화면끼리 오가는 것이라 방향이 없습니다. iOS·Android 기본 탭도 바로 바뀝니다. 움직이면 오히려 느리게 느껴집니다. |
| 모달 · 상세 닫힘 | 닫을 때는 사용자가 이미 다음 행동을 정한 상태라 빨리 사라지는 게 낫습니다. (React에서 퇴장 애니메이션은 언마운트를 늦추는 코드가 필요해, 얻는 것보다 복잡도가 큽니다.) |
| 스크롤에 따른 효과(패럴랙스 등) | 정보를 더하지 않고 멀미와 성능 문제만 생깁니다. |
| 앱을 열 때 목록 | 스플래시(#12)가 이미 시작을 알리므로 목록은 바로 보여 줍니다. |

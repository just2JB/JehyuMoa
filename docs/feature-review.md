# 필요한 기능 검토

기준: README 기획(주요 기능 · 사용 흐름) + Figma 11주차 화면 + 지금 저장소 코드 (2026-11-26).
목표는 "흩어진 학생회 제휴를 모아, **내가 지금 받을 수 있는 혜택**을 쉽게 확인"하는 것입니다.

## 1. 지금 상태

| 기능 | 상태 | 비고 |
| --- | --- | --- |
| 제휴 목록 · 정렬(거리/인기/가나다) | ✅ 동작 | |
| 업종 칩 | ✅ 동작 | '기타'는 현재 데이터가 없어 빈 결과 |
| 검색 | ✅ 동작 | 한글 조합 중 입력 · 초성 검색 · 일치 부분 강조 |
| 소속 · 동행 조건 설정 | ✅ 동작 | 단과대 제휴는 같이 간 사람이 모두 그 단과대일 때만 표시 |
| 매장 상세 | ✅ 동작 | 영업 중 계산, 인원 부족 혜택 안내, 택 1 |
| 지도보기 | ✅ 동작 | 실제 지도(OSM), 핀 묶기, 내 위치 |
| 즐겨찾기 | ✅ 동작 | 기기 안(localStorage)에만 저장 |
| 해시 라우팅 · 링크 공유 | ✅ 동작 | `#/store/:id` |
| 데이터 파일 · 검사 · 기간 만료 | ✅ 동작 | `data/stores.json`, [data-guide](data-guide.md) |
| **제휴 데이터** | ⚠️ 목 데이터 | 실제 공지로 교체 필요 |
| **가게 좌표 · 정문/후문 좌표** | ⚠️ 근사값 | 상세에 '대략적인 위치' 표시 중 |
| 전화 | ⚠️ 버튼만 | 데이터에 전화번호 필드 없음 |
| 최근 본 가게 | ⚠️ 개수만 | 목록 화면 없음 |
| 제보하기 · 공지/이용 안내 | ⚠️ 준비 중 토스트 | |
| 알림 설정 (새 제휴 · 혜택 변경) | ⚠️ 토글만 저장 | 실제 알림을 보낼 수단 없음 |
| 인기순 | ⚠️ 고정 숫자 | 실제 집계할 서버 없음 |

## 2. 검토 결과와 우선순위

**필수**: 없으면 서비스 목표를 못 이루는 것 · **권장**: 신뢰도와 사용성을 크게 올리는 것 · **추후**: 서버 등 기반이 생기면

| # | 기능 | 우선순위 | 근거 | 할 일 |
| --- | --- | --- | --- | --- |
| F1 | 실제 제휴 데이터 입력 | 필수 | 목 데이터로는 서비스가 아님. 형식 · 검사 · 가이드는 준비됨 | 총학 · 단과대 공지 수집 → `stores.json` |
| F2 | 실제 좌표 확인 | 필수 | 거리순 · 지도 · 길찾기가 모두 좌표에 의존. 틀리면 '가까운 순'이 거짓말이 됨 | 가게별 `coordVerified: true`, 정문·후문 좌표 현장 확인 |
| F3 | 데이터 최신성 표시 | 필수 | 학생회 제휴는 학기마다 바뀜. 지난 정보를 보고 갔다가 못 받으면 앱 신뢰가 무너짐. 기간 만료 숨김은 구현됨 | 목록 위에 '○월 ○일 기준' (`updatedAt`) 표시 |
| F4 | 제보하기 | 필수 | 운영자가 모든 공지를 따라가기 어려움. 사용자가 틀린 정보를 알려 줄 길이 있어야 데이터가 유지됨 | 우선 구글 폼 링크로 연결 (가게 id 자동 입력) |
| F5 | 전화번호 | 권장 | 상세에 버튼이 이미 있어 누르면 실망. 영업 여부 확인 수단 | 데이터에 `phone` 필드, `tel:` 링크 |
| F6 | 요일별 영업시간 · 휴무일 | 권장 | 지금은 '매일 같은 시간' 가정이라 휴무일에도 '영업 중'으로 나올 수 있음 | `hours`를 요일별로 확장 |
| F7 | 시간 조건 혜택 구조화 | 권장 | "오후 6시부터", "오후 9시까지" 같은 조건이 글자로만 있음. 지금 받을 수 있는지 계산 불가 | 혜택에 `timeFrom` / `timeTo`, 지금 받을 수 있으면 초록 표시 |
| F8 | 최근 본 가게 목록 | 권장 | 마이 페이지에 개수만 있고 누르면 아무것도 없음 | `#/recent` 화면 |
| F9 | 공지 · 이용 안내 | 권장 | 조건 설정 · 택 1 같은 규칙을 처음 쓰는 사람이 이해할 곳 | 정적 페이지 하나 |
| F10 | 홈 화면에 추가(PWA) · 오프라인 | 권장 | 매장 앞에서 데이터가 약해도 혜택을 보여 줘야 함. 웹앱이라 설치 장벽을 낮출 수 있음 | manifest + 서비스 워커로 마지막 데이터 캐시 |
| F11 | 알림 | 추후 | 웹 푸시는 서버 · 구독 관리가 필요. 그전까지는 토글을 **숨기는 게** 정직함 | 서버 생기기 전엔 토글 숨김 또는 '준비 중' 표시 |
| F12 | 인기순 실제 집계 | 추후 | 즐겨찾기가 기기 안에만 있어 전체 수를 모을 수 없음 | 서버 생기면 집계, 그전엔 인기순 숨김 검토 |
| F13 | 학생 인증 | 추후 | 혜택은 매장에서 학생증으로 확인하므로 앱 인증이 필수는 아님 | 필요해질 때 |
| F14 | 카카오맵 전환 | 추후 | 국내 지도 품질은 좋지만 앱 키 · 도메인 등록 필요. 구조는 준비됨 (`config.js`) | 키 발급 후 |

## 3. 바로 다음에 하면 좋은 순서

1. **F1 + F2** 실제 데이터 · 좌표 (가이드대로 입력만 하면 됨)
2. **F3 + F4** 최신성 표시 · 제보 링크 (작업량 작고 신뢰에 직접 영향)
3. **F5 → F7** 데이터 필드 확장 (전화 · 요일별 영업 · 시간 조건)
4. **F11 · F12** 서버 전까지 동작하지 않는 기능은 숨기거나 '준비 중'으로 표시
